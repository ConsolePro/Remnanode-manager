# Клиентский Xray JSON и хосты

`xray-ru-direct.json` — шаблон Remnawave, а не готовый конфиг конкретного пользователя. Панель добавляет его VLESS outbound первым через `remnawave.addVirtualHostAsOutbound`. В файле нет чужих адресов, UUID и ключей из рабочего примера.

1. В клиенте настрой обновление **обоих** файлов `geoip.dat` и `geosite.dat` из [runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat). Нужны категории `category-ru`, `ru-blocked`, `private`, `yandex`, `mailru` в GeoSite и `ru`, `ru-blocked`, `private` в GeoIP. Другие базы могут не содержать эти категории и привести к отказу запуска Xray.
2. Запусти `sudo remnanode clients` → «Шаблон РФ-direct». Выбери хосты. Менеджер создаёт/обновляет отдельный шаблон `RNM RU Direct`, делает backup и назначает его выбранным хостам через API. Стандартный шаблон панели не перезаписывается.
3. Обнови подписку в клиенте с поддержкой полного Xray JSON. При ручной настройке скопируй этот JSON в отдельный Xray JSON-шаблон панели и назначь его нужным хостам.
4. Проверь **отрендеренный** конфиг: первый outbound имеет tag `proxy`, содержит параметры текущего пользователя; есть `direct` и `block`. Служебное поле `remnawave` обрабатывает панель. Не запускай исходный шаблон напрямую через Xray.

Порядок маршрутов: DNS самого Xray напрямую, BitTorrent в блок, приватные ресурсы напрямую, заблокированные RU-домены через прокси, остальные российские домены напрямую, заблокированные RU-IP через прокси, оставшиеся российские IP напрямую. Несовпавший трафик использует первый outbound `proxy`. Catch-all в одиночном шаблоне отсутствует, чтобы `IPIfNonMatch` мог проверить IP неизвестного домена. Доменное правило имеет приоритет над IP-правилом; принадлежность сайтов к категориям определяется выбранными базами.

DNS повторяет простую схему рабочего примера: Yandex DoH с bootstrap IP, резервный Yandex UDP. Нет `expectIPs`, ограничений ответа страной и фильтрации AAAA/HTTPS ответов. Предпочтение IPv4 относится к резолвингу Xray, не отключает IPv6 ОС и не заменяет DNS-настройки браузера/TUN. Локальные SOCKS/HTTP слушают только `127.0.0.1`; адаптер TUN настраивает приложение.

Балансировщик создаётся тем же меню и отдельным шаблоном `RNM Auto <hash>` (имя можно задать вручную; существующее имя обновляет соответствующий шаблон). Панель должна поддерживать `remnawave.injectHosts`. Выбранные существующие хосты получают этот шаблон, остаются видимыми; вспомогательные клоны, скрытие исходных хостов и изменение групп автоматически не выполняются. Пользователю нужен доступ ко всем участникам. Убедись, что рендеринг даёт несколько outbound `proxy`, `proxy-2`, … и правила ссылаются на `balancerTag: auto`. Если панель возвращает неполный набор, исправь доступы/группы или состав балансировщика. `leastPing` работает с `burstObservatory`; при отказе всех участников fallback — `block`.

Для диагностики проблем с картинками открой инструменты разработчика браузера и найди домен недогрузившегося ресурса. Проверь его DNS и фактический маршрут отдельно от основного сайта. Серверный direct остаётся выходом с IP сервера: для обхода географических ограничений РФ используй клиентский direct или мост на российский сервер. Приложения, определяющие наличие VPN-интерфейса, могут требовать исключения из VPN в настройках самого клиента.

Изменение шаблона не исправляет активные подключения до обновления подписки/переподключения. Проверяй хотя бы одну российскую страницу с её ресурсами, зарубежный сайт, выходной IP и поведение при недоступном прокси.
